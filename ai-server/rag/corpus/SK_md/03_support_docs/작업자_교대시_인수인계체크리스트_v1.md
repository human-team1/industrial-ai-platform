# 작업자 교대시 인수인계 체크리스트

샘플 매뉴얼 v1

산업 이미지 이상탐지 프로젝트 - RAG/LLM 문서셋

## 1. 문서 목적

본 문서는 산업 이미지 이상탐지 프로젝트에서 현장 작업자가 교대 근무 시 확인하고 전달해야 하는 정보를 표준화하기 위한 체크리스트이다.

본 프로젝트는 이미지 업로드 분석과 실시간 프레임 분석을 통해 anomaly score, 정상/재검사/불량 의심 판정, heatmap/anomaly map, result artifact를 제공한다. 교대 시점에 미처리 재검사 건, 불량 의심 건, 반복 이상, 설비 상태, 저장 오류, 알림 내역이 제대로 전달되지 않으면 다음 작업자가 동일 문제를 반복 확인하거나 중요한 이상 상황을 놓칠 수 있다.

이 문서는 다음 목적을 가진다.

교대 전후 작업자가 확인해야 할 검사 결과, 재검사 건, 불량 의심 건을 표준화한다.

반복 이상, 설비 상태, 카메라/조명/센서 상태, result artifact 저장 상태를 다음 근무자에게 명확히 전달한다.

미처리 건과 후속 조치 담당자를 구분하여 현장 대응 누락을 줄인다.

결과 상세 화면, 알림, 운영 모니터링, RAG/LLM 질의응답을 교대 업무와 연결한다.

교대 인수인계 내용을 향후 운영 로그, 후속 확인 이력, 오탐/미탐 보고서 작성의 근거로 활용할 수 있도록 한다.

본 문서는 인사/근태 관리용 문서가 아니라, 이상감지 서비스 운영 과정에서 필요한 검사 결과와 설비 상태를 전달하기 위한 운영형 샘플 문서이다. 실제 DB/ERD 연계는 부록에서 참고용으로 다룬다.

| 미처리 재검사 존재 | 재검사 대상 결과의 원인과 후속 조치 전달 |

## 5. 미처리 재검사 및 불량 의심 건 관리

미처리 재검사와 불량 의심 건은 교대 시 가장 우선적으로 전달해야 한다. 특히 저신뢰 또는 경계 구간 결과는 다음 근무자가 동일 조건 재촬영, 원본 확인, 후속 확인을 이어서 수행할 수 있도록 구체적으로 남겨야 한다.

### 5.1 미처리 재검사 건 분류 기준

| 분류 | 기준 | 처리 방향 |
| --- | --- | --- |
| 경계 구간 결과 | anomaly score가 threshold 근처에 위치한 경우 | 원본 이미지와 heatmap 위치를 확인하고 재검사 |
| 저신뢰 결과 | 조명, 초점, ROI, 입력 품질 문제로 결과 신뢰도가 낮은 경우 | 촬영 조건 점검 후 재촬영 |
| heatmap 불명확 | heatmap이 약하거나 넓게 퍼져 실제 결함이 불명확한 경우 | 정상 샘플과 비교하고 반복 여부 확인 |

| 반복 재검사 | 같은 설비/카테고리/위치에서 재검사가 반복되는 경우 | 후속 확인 및 설비 상태 확인 요청 |

## 6. 반복 이상 및 설비 상태 공유 기준

반복 이상은 단발성 불량 의심보다 운영 리스크가 크다. 같은 설비, 같은 카테고리, 같은 이상 위치, 같은 시간대에 이상이 반복되면 교대 시 반드시 공유한다.

| 동일 결함 유형 반복 | 스크래치, 오염, 균열, 연결 이상 등 유사 유형 반복 |

## 9. 작업자 주의사항

인수인계는 근태 기록이 아니라 이상감지 운영 상태를 전달하기 위한 절차이다.

불량 의심은 자동 확정 불량을 의미하지 않으며, 원본 이미지와 heatmap, 재검사 결과를 함께 확인해야 한다.

미처리 재검사 건과 불량 의심 건은 다음 근무자에게 반드시 전달한다.

동일 위치 또는 동일 설비에서 반복된 이상은 단발성 결과보다 우선적으로 공유한다.

score가 낮더라도 원본 이미지에서 명확한 결함이 보이면 재검사 또는 후속 확인을 요청한다.

result artifact 저장 실패가 있으면 사후 분석이 어려우므로 반드시 보고 필요 항목으로 기록한다.

threshold 변경이나 모델 설정 변경은 작업자가 임의로 수행하지 않는다.

문서에 없는 원인은 단정하지 않고 결과 기록과 후속 확인을 통해 확인한다.

| INSPECTION_RESULT | 검사 결과와 판정 정보 관리 |
| RESULT_ARTIFACT | 원본 이미지, heatmap, 결과 JSON/CSV 등 산출물 관리 |
| REVIEW_QUEUE | 재검사 또는 후속 확인 대상 관리 |
| REVIEW_HISTORY | 후속 확인 결과와 판정 변경 이력 관리 |
| NOTIFICATION | 알림 발생 및 확인 상태 관리 |
| OPERATION_LOG | 운영 중 발생한 시스템 이벤트 기록 |
| AUDIT_LOG | 관리자 조치, 설정 변경, 주요 이벤트 감사 로그 기록 |

## 부록 A. 인수인계 이력 저장을 위한 추가 테이블 검토

MVP 단계에서는 인수인계 내용을 문서 또는 메모로 관리할 수 있다. 다만 서비스에서 교대 인수인계 이력을 직접 저장하고 조회하려면 다음 테이블 추가를 검토할 수 있다.

| 테이블 | 관리 목적 |
| --- | --- |
| SHIFT_HANDOVER | 교대 단위 인수인계 헤더 정보 관리 |
| SHIFT_HANDOVER_ITEM | 미처리 재검사, 불량 의심, 반복 이상, 설비 상태 등 세부 항목 관리 |

## 부록 B. SHIFT_HANDOVER 권장 필드

| 필드 | 설명 |
| --- | --- |
| handover_id | 인수인계 기록 ID |
| handover_at | 인수인계 일시 |
| from_worker_id | 인계자 ID |
| to_worker_id | 인수자 ID |
| line_id | 담당 라인 또는 설비 ID |
| shift_type | 주간/야간/교대 구분 |
| summary | 교대 요약 |
| overall_status | 정상/주의/점검 필요/인수인계 필요 |
| admin_notified | 후속 전달 여부 |
| created_at | 기록 생성 시각 |

## 부록 C. SHIFT_HANDOVER_ITEM 권장 필드

| 필드 | 설명 |
| --- | --- |
