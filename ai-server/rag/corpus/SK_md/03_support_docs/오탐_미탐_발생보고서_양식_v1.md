# 오탐/미탐 발생보고서 양식

샘플 매뉴얼 v1

산업 이미지 이상탐지 프로젝트 - RAG/LLM 문서셋

## 1. 문서 목적

본 문서는 산업 이미지 이상탐지 프로젝트에서 false positive와 false negative가 의심되거나 확인된 경우 원인 분석과 후속 조치를 기록하기 위한 보고서 양식이다.

오탐과 미탐은 모델 성능뿐 아니라 조명, 초점, ROI, 제품 위치, 정상 변동, threshold 설정 등 다양한 요인에 의해 발생할 수 있다. 따라서 발생 사례를 일관된 형식으로 기록해야 반복 원인을 분석하고 운영 기준을 개선할 수 있다.

이 문서는 오탐/미탐 정의, 발생보고서 기록 양식, 원인 분류 기준, 후속 조치 기준을 제공하며 RAG 기반 문서 질의응답과 모델 운영 개선의 근거 문서로 사용한다.

## 2. 적용 범위

| 항목 | 내용 |
| --- | --- |
| 데이터셋 | MVTec AD |

설비 점검이나 모델 성능 검토가 필요한 사례는 후속 조치 대상으로 기록하고, 운영 기준에 따라 관련 담당자와 협의한다.

## 3. 오탐/미탐 정의

| 발생 유형 | 정의 | 대표 상황 |
| --- | --- | --- |
| 오탐(False Positive) | 실제 정상 이미지 또는 정상 변동을 모델이 이상 또는 불량 의심으로 판단한 경우 | 정상 제품이 조명 반사, 위치 변화, 정상 질감 차이 때문에 높은 score 또는 강한 heatmap을 보임 |
| 미탐(False Negative) | 실제 이상 이미지 또는 결함 영역을 모델이 정상 또는 낮은 이상으로 판단한 경우 | 원본 이미지에는 스크래치, 균열, 파손이 보이지만 score가 낮거나 heatmap 반응이 약함 |
| 저신뢰 반복 | 이미지 품질이나 촬영 조건 문제로 명확한 판정이 반복적으로 어려운 경우 | 초점 흐림, ROI 누락, 조명 불균형, trigger 오류가 반복됨 |
| 판단 불일치 | 작업자 육안 판단과 모델 판정이 다르게 나타나는 경우 | 모델은 불량 의심이지만 작업자는 정상으로 보거나, 반대 상황이 발생함 |

## 4. 발생보고서 기록 양식

오탐 또는 미탐 사례가 확인되면 아래 항목을 기준으로 보고서를 작성한다. 실제 시스템에서는 이 항목을 화면 입력 폼, CSV, JSON 또는 운영 DB에 저장할 수 있다.

| 기록 항목 | 작성 내용 |
| --- | --- |
| 보고서 ID | 오탐/미탐 사례를 식별하기 위한 ID |
| 발생 일시 | 사례가 발생하거나 확인된 날짜와 시간 |
| 작성자 | 보고서를 작성한 작업자 또는 관리자 |
| 검사 ID | 해당 사례와 연결된 검사 결과 ID |
| 카테고리 | bottle, cable, capsule, hazelnut, metal_nut, carpet, grid, leather, tile, wood 중 해당 카테고리 |
| 발생 유형 | 오탐, 미탐, 저신뢰 반복, 판단 불일치 중 선택 |
| 모델 버전 | 해당 결과를 생성한 모델명 또는 model version |
| threshold 설정 정보 | 적용된 threshold 버전, threshold profile, 또는 설정 파일 ID |
| anomaly score | 모델이 산출한 이상 점수 |
| 판정 결과 | 판정 결과: 정상, 재검사, 불량 의심 중 모델 판정 |
| 추가 상태/사유 | 저신뢰, 반복 감지, 촬영 조건 의심 등 해당 사례의 추가 상태를 기록 |
| heatmap 집중 위치 | 모델이 이상 가능성이 높다고 본 위치 또는 반응이 약했던 위치 |
| 추정 결함 유형 | object: 형태 변형/깨짐/오염/연결 이상 등, texture: 스크래치/오염/균열/패턴 깨짐 등 |
| 원본 확인 결과 | 작업자가 원본 이미지에서 실제 결함 또는 정상 상태를 확인한 내용 |
| 확인 상태 | 의심 / 확인 중 / 오탐 확정 / 미탐 확정 / 판단 보류 중 선택 |
| 재검사 결과 | 재촬영 또는 재검사 후 확인된 판정과 heatmap 변화 |
| 심각도 | 낮음 / 중간 / 높음 / 긴급 중 선택 |
| 영향 범위 | 단일 이미지 / 동일 카테고리 반복 / 특정 설비 반복 / 운영 기준 영향 중 선택 |
| 추정 원인 | 조명 반사, 초점 흐림, ROI 문제, 위치 변화, threshold 문제, 모델 한계 등 |
| 후속 조치 | 설비 점검, threshold 검토, 정상 샘플 보강, 모델 후보 검토, 문서/SOP 보완 등 |
| 학습 후보 여부 | 향후 모델 재학습, threshold 검증, few-shot reference 보강 등에 사용할 후보인지 여부 |
| 첨부 자료 | 원본 이미지, heatmap, anomaly map, 결과 JSON/CSV, 재검사 이미지 등 |
| 비고 | 반복 여부, 유사 사례, 후속 확인 의견 |

오탐/미탐 사례 중 반복 발생하거나 원인이 명확한 사례는 향후 모델 개선, threshold 검증, 정상 샘플 보강, RAG 문서 보완의 후보로 관리한다.

## 5. 원인 분류 기준

| 원인 분류 | 설명 | 확인 방법 |
| --- | --- | --- |
| 촬영 조건 문제 | 조명 반사, 그림자, 초점 흐림, 과노출/저노출, motion blur 등 | 원본 이미지와 재촬영 결과를 비교하고 카메라/조명 상태를 점검한다. |
| ROI/Crop 문제 | 검사 대상이 잘리거나 배경이 과도하게 포함되어 score 또는 heatmap에 영향을 준 경우 | ROI 설정, crop margin, 제품 위치 정렬 상태를 확인한다. |
| 정상 변동 문제 | 정상 제품의 형태, 질감, 색상, 배치 차이가 모델에 이상처럼 보인 경우 | 정상 샘플 다수와 비교하고 정상 변동 범위를 문서화한다. |
| 결함 미세성 문제 | 작은 점, 얇은 스크래치, 미세 균열처럼 결함이 작아 모델 반응이 약한 경우 | 원본 확대, 입력 해상도, pixel-level heatmap 품질을 확인한다. |
| Threshold 문제 | 모델 score 분포와 운영 threshold가 맞지 않아 오탐/미탐이 증가한 경우 | 카테고리별 score 분포, F1-score, 오탐/미탐 비율을 검토한다. |
| 모델 한계 | 특정 카테고리 또는 결함 유형에서 모델이 일관되게 약한 경우 | category별 AUROC, PRO, worst category, 실패 사례를 함께 확인한다. |
| 문서/SOP 부족 | 작업자 판단 기준이나 기록 기준이 불명확하여 사례 분류가 어려운 경우 | 관련 문서와 체크리스트를 보완한다. |

## 6. 후속 조치 기준

| 발생 패턴 | 후속 조치 | 담당자 |
| --- | --- | --- |
| 동일 카테고리에서 오탐 반복 | 조명/ROI/정상 변동을 점검하고, 필요 시 설비 점검 또는 정상 샘플 보강을 검토한다. | 후속 조치 담당자 |
| 동일 결함 유형에서 미탐 반복 | 입력 해상도, heatmap 품질, 모델 후보, threshold를 후속 확인 대상으로 기록한다. | 후속 조치 담당자 |
| 특정 설비/시간대에서 저신뢰 반복 | 카메라, 조명, 컨베이어, 센서/trigger 상태 점검을 요청한다. | 후속 조치 담당자 |
| 작업자 판단과 모델 결과 불일치 반복 | 판정 기준서, SOP, 재검사 기록을 확인하고 문서 보완 여부를 검토한다. | 후속 조치 담당자 |
| threshold 변경 필요 의심 | 검증 데이터와 성능 지표를 확인한 뒤 관리자 권한과 승인 절차에 따라 변경을 검토한다. | 관리자 |
| 심각한 미탐 가능성 | 후속 확인을 우선 수행하고 필요 시 운영 판정 기준을 임시 보수적으로 적용한다. | 후속 조치 담당자 |
| 반복 오탐/미탐 또는 원인이 명확한 사례 | 학습 후보 또는 검증 후보로 등록하고 후속 확인을 요청한다. | 후속 조치 담당자 |

## 7. 보고서 작성 시 주의사항

오탐/미탐 원인을 단정하지 않고 원본 이미지, heatmap, 재검사 결과, 촬영 조건을 함께 확인한다.

threshold 변경은 작업자가 임의로 수행하지 않고 후속 확인와 승인 절차를 따른다.

미탐 의심 사례는 운영 리스크가 크므로 원본 결함 위치와 모델 반응 여부를 반드시 기록한다.

반복 사례는 단일 사례보다 중요하므로 카테고리, 시간대, 설비, 모델 버전 기준으로 묶어 분석한다.

보고서에 사용한 원본 이미지와 heatmap은 result artifact와 연결하여 추적 가능하게 보관한다.

미탐이 의심될 때 가장 먼저 확인해야 하는 것은 무엇인가?

조명 반사로 인한 오탐은 어떻게 판단할 수 있나?

threshold 문제로 의심될 때 작업자가 직접 설정을 변경해도 되나?

동일 카테고리에서 오탐이 반복되면 어떤 후속 조치를 검토해야 하나?

미세 결함이 미탐될 때 어떤 지표나 자료를 함께 확인해야 하나?

오탐/미탐 보고서는 RAG/LLM 서비스에서 어떻게 활용될 수 있나?

저신뢰 반복은 오탐/미탐과 어떻게 다르게 기록해야 하나?
오탐/미탐 사례를 학습 후보로 등록하는 기준은 무엇인가?
오탐/미탐 보고서에서 심각도와 영향 범위는 왜 기록해야 하나?
