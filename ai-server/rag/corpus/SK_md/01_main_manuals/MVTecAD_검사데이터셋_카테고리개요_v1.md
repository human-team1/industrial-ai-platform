# MVTecAD 검사데이터셋 카테고리 개요

샘플 매뉴얼 v1

산업 이미지 이상탐지 프로젝트 - RAG/LLM 문서셋

## 1. 문서 목적

본 문서는 산업 이미지 이상탐지 프로젝트에서 사용하는 MVTec AD 데이터셋의 구조와 카테고리 구성을 설명하기 위한 문서이다.

본 프로젝트는 이미지 기반 이상탐지 모델을 통해 제품의 정상/이상 여부를 판단하고, 이상 점수, 판정 결과, Heatmap 또는 Anomaly Map을 제공하는 것을 목표로 한다. 따라서 작업자와 관리자가 모델 결과를 해석하려면, 먼저 사용 데이터셋의 카테고리와 결함 유형을 이해해야 한다.

이 문서는 이후 작성되는 object 계열 결함 해석 가이드, texture 계열 결함 해석 가이드, Heatmap 해석 가이드, 정상/재검사/불량 판정 기준서의 기준 문서로 사용한다.

## 2. 적용 범위

| 항목 | 내용 |
| --- | --- |
| 데이터셋 | MVTec AD |
| 적용 목적 | 산업 이미지 이상탐지 모델 실험 및 결과 설명 |
| 사용 방식 | 정상 이미지 기반 학습 또는 feature memory 구성 후 test image 평가 |
| 적용 기능 | 이미지 업로드 분석, 실시간 프레임 분석, 결과 상세 설명, RAG 기반 문서 질의응답 |
| 관련 결과 | anomaly score, image-level 판정, pixel-level heatmap, anomaly map |
| 관련 사용자 | 현장 작업자, 관리자 |

본 문서에서는 프로젝트 초기 실험에서 사용할 MVTec AD의 object 5개, texture 5개 카테고리를 기준으로 설명한다.

## 3. MVTec AD 데이터셋 개요

MVTec AD는 산업 검사 환경에서 이상탐지 모델을 평가하기 위해 만들어진 이미지 데이터셋이다. 데이터셋은 여러 object 및 texture 카테고리로 구성되어 있으며, 각 카테고리에는 정상 이미지와 결함 이미지가 포함된다.

| 항목 | 설명 |
| --- | --- |
| 데이터 유형 | 산업 제품 및 표면 이미지 |
| 카테고리 구조 | object 계열과 texture 계열로 구성 |
| 학습 데이터 | defect-free normal image 중심 |
| 테스트 데이터 | normal image와 anomalous image 포함 |
| 평가 목적 | 이미지 단위 이상탐지와 픽셀 단위 결함 위치 탐지 |
| 결과 해석 | anomaly score와 heatmap/anomaly map으로 해석 |

MVTec AD는 결함 이미지가 충분하지 않은 산업 현장 상황을 가정하기에 적합하다. 실제 산업 환경에서는 불량 데이터가 적거나 결함 유형이 다양하게 나타나기 때문에, 정상 이미지를 기준으로 이상 여부를 판단하는 방식이 자주 사용된다.

## 4. 프로젝트에서 사용하는 카테고리

본 프로젝트 초기 실험에서는 MVTec AD 전체 카테고리 중 object 5개와 texture 5개를 우선 사용한다. 사용 카테고리는 bottle, cable, capsule, hazelnut, metal_nut, carpet, grid, leather, tile, wood로 한다. 이후 실험 범위가 변경되는 경우 문서 버전을 갱신한다.

### 4.1 Object 계열

Object 계열은 제품의 형태, 구조, 부품 위치, 누락, 변형 여부가 중요한 카테고리이다.

| 카테고리 | 주요 확인 관점 | 예시 이상 유형 |
| --- | --- | --- |
| bottle | 전체 형태, 표면 오염, 파손 여부 | 깨짐, 오염, 형태 이상 |
| cable | 선의 배치, 연결부 위치, 꼬임 여부 | 꼬임, 꺾임, 연결 이상 |
| capsule | 표면 상태, 형태, 찍힘 여부 | 균열, 오염, 찍힘, 변형 |
| hazelnut | 전체 형태, 표면 손상, 깨짐 여부 | 균열, 찍힘, 오염, 형태 이상 |
| metal_nut | 금속 표면, 구멍/나사산 주변, 형태 변형 | 스크래치, 찍힘, 변형, 오염 |

Object 계열에서는 제품의 전체 구조, 외곽 형태, 표면 손상, 연결부 또는 구멍 주변의 이상 여부가 중요하다. Heatmap이 제품 경계, 연결부, 표면 손상 부위, 구멍 주변, 금속 표면의 국소 영역에 집중되는 경우 실제 구조적 이상 가능성을 우선 확인한다.

### 4.2 Texture 계열

Texture 계열은 제품 전체의 형태보다 표면 패턴, 반복 무늬, 질감 변화, 오염, 스크래치가 중요한 카테고리이다.

| 카테고리 | 주요 확인 관점 | 예시 이상 유형 |
| --- | --- | --- |
| carpet | 반복 패턴, 표면 얼룩, 국소 손상 | 패턴 깨짐, 오염, 얼룩 |
| grid | 격자 반복 구조, 선 끊김, 미세 결함 | 패턴 깨짐, 선 끊김, 국소 결함 |
| leather | 표면 질감, 스크래치, 색상 변화 | 스크래치, 오염, 질감 변화 |
| tile | 표면 균열, 오염, 색상 변화 | 균열, 오염, 표면 파손 |
| wood | 나뭇결, 스크래치, 찍힘, 색상 변화 | 스크래치, 찍힘, 결 변화 |

Texture 계열에서는 작은 표면 결함이 중요하다. 이미지 해상도, 조명, 초점 상태가 결과에 큰 영향을 줄 수 있으며, Heatmap이 얇은 선, 작은 점, 반복 패턴이 깨진 위치에 나타나는 경우 표면 결함 가능성을 확인한다.

## 5. Object 계열과 Texture 계열의 차이

| 구분 | Object 계열 | Texture 계열 |
| --- | --- | --- |
| 주요 관심 | 제품 구조, 형태, 부품 위치 | 표면 패턴, 질감, 반복 무늬 |
| 대표 이상 | 누락, 변형, 파손, 조립 이상 | 스크래치, 균열, 오염, 패턴 깨짐 |
| Heatmap 해석 | 제품 경계, 연결부, 구멍 주변, 표면 손상, 구조 변화 위치 확인 | 표면의 국소 변화, 반복 패턴 이상 확인 |
| 작업자 확인 | 정상 제품 형태와 비교 | 정상 표면 패턴과 비교 |
| 주의사항 | 위치 변화와 실제 결함 구분 필요 | 조명 반사, 얼룩, 초점 흐림과 구분 필요 |

Object 계열에서는 “정상 구조와 다른가”가 중요하고, Texture 계열에서는 “정상 표면 패턴과 다른가”가 중요하다.

## 6. 데이터셋과 우리 프로젝트의 연결

| 목적 | 설명 |
| --- | --- |
| 모델 성능 평가 | object/texture 카테고리에서 image-level 및 pixel-level 성능 확인 |
| 결과 설명 검증 | anomaly score와 heatmap을 작업자가 이해할 수 있는지 확인 |
| RAG 문서 테스트 | 결함 유형, 대응 절차, 판정 기준에 대한 문서 검색 테스트 |
| 프론트 실시간 분석 검토 | 실시간 분석에서 요구되는 응답 지연, 갱신 주기, 화면 표시 안정성을 검토 |
| 업로드 정밀 분석 검토 | 업로드 이미지/영상 분석에서 pixel-level 결과, heatmap 품질, 처리 시간을 확인 |

실시간 분석의 결과 갱신 주기와 허용 지연 시간은 모델 구조, 입력 해상도, 서버 자원, 운영 요구사항에 따라 별도로 검증한다. 본 문서에서는 특정 수치를 고정하지 않고, 실시간 적용 가능성을 검토하는 관점만 설명한다.

MVTec AD는 실제 산업 설비 데이터를 그대로 대체하는 것은 아니지만, 초기 이상탐지 모델 실험과 RAG 기반 설명 기능을 검증하기 위한 대표 benchmark로 활용할 수 있다.

### 6.1 모델 평가 지표 개요

본 프로젝트에서 사용하는 모델 평가지표는 작업자가 직접 계산하기 위한 값이 아니라, 모델이 서비스에 적용 가능한지 판단하기 위한 기준이다. 작업자는 주로 anomaly score, 판정 결과, heatmap/anomaly map을 확인하고, 관리자는 아래 지표를 함께 참고한다.

| 지표 | 의미 | 서비스 관점 해석 |
| --- | --- | --- |
| Image-level AUROC | 이미지 단위로 정상/이상을 구분하는 성능 | 모델이 정상 이미지와 이상 이미지를 전반적으로 잘 구분하는지 확인 |
| Pixel-level AUROC | 픽셀 단위로 이상 위치를 구분하는 성능 | heatmap/anomaly map이 실제 결함 위치를 잘 가리키는지 확인 |
| PRO | 결함 영역 단위의 위치 탐지 성능 | 작은 결함 또는 불규칙한 결함 영역을 얼마나 잘 잡는지 확인 |
| F1-score | Precision과 Recall의 균형 | threshold 적용 후 정상/불량 의심 판정이 얼마나 균형적으로 이루어지는지 확인 |
| FPS 또는 images/sec | 단위 시간당 처리 가능한 이미지 수 | 실시간 분석에서 요구되는 처리 속도와 화면 갱신 지연을 만족하는지 확인 |
| Peak GPU Memory | 추론 중 필요한 최대 GPU 메모리 | 운영 서버에서 안정적으로 실행 가능한지 확인 |
| MVTec AD → MVTec AD2 성능 변화 | 기존 MVTec AD 기준 성능이 MVTec AD2 평가 조건에서도 유지되는지 확인하는 지표 | 모델이 기존 benchmark 조건에서만 잘 동작하는지, 더 어려운 데이터 조건에서도 안정적인지 확인 |

이 문서에서는 각 지표의 개념만 설명하고, 구체적인 수치와 모델별 비교 결과는 별도의 모델 실험 결과 문서에서 관리한다.

MVTec AD → MVTec AD2 성능 변화는 실제 AI 모델 성능 실험 파트에서 별도로 측정한다. 본 문서에서는 해당 지표의 개념과 서비스 관점에서의 의미만 설명하며, 구체적인 수치와 모델별 비교 결과는 모델 실험 결과 문서에서 관리한다.

## 7. 탐지 결과의 기본 구성

| 결과 항목 | 설명 |
| --- | --- |
| category | 검사 대상 카테고리 |
| anomaly score | 이미지 전체의 이상 가능성 점수 |
| confidence | 판정 결과에 대한 신뢰도 또는 보조 신뢰 지표 |
| decision | 정상, 재검사, 불량 의심 등의 판정 결과 |
| threshold info | 판정 시 적용된 threshold 값, threshold 출처, threshold 버전 정보 |
| heatmap | 이상 가능성이 높은 위치를 색상으로 표시한 지도 |
| anomaly map | 픽셀 또는 패치 단위 이상 점수 지도 |
| model version | 결과를 생성한 모델 버전 |
| result statuts | 검사 성공, 실패, 후속 확인 대상, 수정 완료 등 결과 처리 상태 |
| result artifact | 저장된 원본 이미지, heatmap, 결과 파일 |

작업자는 anomaly score만으로 최종 판단하지 않고, 원본 이미지와 heatmap 위치를 함께 확인해야 한다.

Image-level AUROC, Pixel-level AUROC, PRO, F1-score와 같은 모델 평가지표는 작업자 화면에서 매번 확인하는 값이 아니라, 모델 후보 선정과 운영 안정성 검토를 위해 관리자가 참고하는 지표이다.

## 8. Anomaly Score 해석 기준

Anomaly score는 이미지 전체가 정상 이미지와 얼마나 다른지를 나타내는 값이다. 점수가 높을수록 모델이 이상 가능성을 높게 본다는 의미이다. 다만 anomaly score는 확정 불량 판정이 아니다. 조명 반사, 초점 흐림, 위치 흔들림, 배경 변화 등으로 인해 점수가 높아질 수 있다.

본 문서에서 사용하는 score 낮음/중간/높음은 고정된 수치 기준이 아니라, 모델 실험 결과 확정 전 사용하는 정성적 표현이다. 실제 운영 시에는 모델 버전, 카테고리, 검증 데이터에 따라 threshold를 별도로 설정한다.

| 상황 | 해석 | 권장 조치 |
| --- | --- | --- |
| score 낮음 | 정상 가능성이 높음 | 정상 처리 가능 |
| score 중간 | 경계 구간 또는 저신뢰 결과 가능 | 재검사 권장 |
| score 높음 | 이상 가능성이 높음 | 원본 이미지와 heatmap 확인 |
| score 높음 + heatmap 국소 집중 | 실제 결함 가능성 높음 | 후속 확인 또는 불량 의심 등록 |
| score 높음 + heatmap 넓게 분산 | 조명/초점/배경 문제 가능 | 설비 상태 확인 후 재촬영 |

정확한 임계값은 모델 버전, 카테고리, 검증 결과에 따라 별도로 설정한다.

## 9. Heatmap / Anomaly Map 기본 해석

Heatmap 또는 Anomaly Map은 모델이 이상 가능성이 높다고 판단한 위치를 시각적으로 보여준다.

| Heatmap 형태 | 가능 해석 | 확인 항목 |
| --- | --- | --- |
| 작은 점 형태 | 국소 결함, 오염, 찍힘 가능성 | 원본 확대 확인 |
| 얇은 선 형태 | 스크래치, 균열 가능성 | 표면 결함 여부 확인 |
| 부품 경계 집중 | 조립 이상, 위치 어긋남, 경계 오탐 가능성 | 정상 샘플과 위치 비교 |
| 넓게 퍼짐 | 조명, 초점, 배경 변화 가능성 | 촬영 조건 확인 |
| 반복 패턴 일부 집중 | texture 패턴 깨짐 가능성 | 주변 반복 구조와 비교 |

Heatmap은 확정 불량 위치가 아니라 점검 우선 영역이다. 작업자는 Heatmap 위치와 원본 이미지를 함께 보고 실제 결함 여부를 확인해야 한다.

Pixel-level AUROC와 PRO는 이러한 heatmap/anomaly map이 실제 결함 위치를 얼마나 잘 가리키는지 평가하기 위한 지표이다. Pixel-level AUROC는 픽셀 단위의 구분 성능을 보고, PRO는 결함 영역 단위로 위치 탐지 품질을 확인한다.

Heatmap 품질에 대한 자세한 해석 기준은 별도 문서인 `Heatmap_AnomalyMap_해석가이드_v1`에서 다룬다.

## 10. 기본 판정 결과와 추가 상태

### 10.1 기본 판정 결과 표

| 판정 | 의미 | 작업자 조치 |
| --- | --- | --- |
| 정상 | 이상 점수가 낮고 heatmap이 뚜렷하지 않음 | 정상 처리 |
| 재검사 | 점수가 경계 구간이거나 heatmap이 불명확함 | 동일 조건 재촬영, 원본 확인 |
| 불량 의심 | 점수가 높고 heatmap이 결함 위치에 집중됨 | 후속 확인 또는 불량 의심 등록 |

판정 결과는 모델의 자동 판단 결과이며, 실제 운영에서는 재검사 결과와 후속 확인을 함께 고려한다.

정상, 재검사, 불량 의심 판정은 anomaly score와 threshold를 기준으로 결정된다. F1-score는 threshold를 적용했을 때 정상/불량 의심 판정이 얼마나 균형적으로 이루어지는지 확인하는 지표이다. 단, threshold 값은 모델 버전, 카테고리, 검증 데이터에 따라 달라질 수 있으므로 문서에서 임의로 고정하지 않는다.

오탐은 정상 이미지를 이상으로 판단한 경우이고, 미탐은 이상 이미지를 정상으로 판단한 경우이다. 재검사 구간은 오탐과 미탐을 줄이기 위해 경계 점수대의 결과를 작업자가 다시 확인하도록 설정하는 영역이다.

### 10.2 추가 상태 또는 재검사 사유 표

| 추가 상태/사유 | 의미 | 작업자 조치 |
| --- | --- | --- |
| 저신뢰 | 이미지 품질, 조명, 초점, 입력 상태 문제로 판정 신뢰가 낮은 상태 | 촬영 조건 점검 후 재촬영 |
| 반복 감지 | 재검사 또는 반복 촬영에서 동일 위치에 heatmap이 반복적으로 나타나는 상태 | 결과 기록 및 후속 확인 요청 |
| 촬영 조건 의심 | heatmap이 넓게 퍼지거나 배경/조명 변화와 함께 나타나는 상태 | 조명, 초점, 위치, 배경 확인 후 재촬영 |

저신뢰와 반복 감지는 기본 판정 결과가 아니라 재검사 사유 또는 추가 상태로 관리한다. 기본 판정은 정상, 재검사, 불량 의심을 기준으로 표시하고, 필요한 경우 추가 상태를 함께 기록한다.

## 11. 작업자 기본 확인 절차

1. 검사 카테고리를 확인한다.

2. anomaly score와 판정 결과를 확인한다.

3. 원본 이미지를 확인한다.

4. Heatmap 또는 Anomaly Map이 집중된 위치를 확인한다.

5. 해당 위치가 실제 결함인지 육안으로 확인한다.

6. 조명 반사, 초점 흐림, 위치 흔들림이 있는지 확인한다.

7. 필요한 경우 동일 조건으로 재촬영한다.

8. 재검사 또는 반복 촬영에서도 동일 위치에 heatmap이 반복적으로 나타나면 반복 감지 추가 상태로 기록하고 후속 확인 대상으로 기록한다.

9. 최종 조치 결과를 기록한다.

## 12. 주의사항

- MVTec AD는 산업 이상탐지 연구용 benchmark이며, 실제 현장 설비의 모든 조건을 대표하지는 않는다.

- Heatmap은 확정 불량 위치가 아니라 점검 우선 영역이다.

- Anomaly score가 높더라도 조명, 초점, 배경, 위치 변화로 인한 오탐 가능성이 있다.

- 정상/재검사/불량 임계값은 모델 버전과 카테고리별 검증 결과에 따라 별도로 설정해야 한다.

- 문서에 없는 원인은 단정하지 않는다.

- 최종 판단은 원본 이미지, 모델 결과, 재검사 결과, 후속 확인을 함께 고려한다.

- 모델 평가지표는 모델 선택과 운영 검토를 위한 기준이며, 개별 검사 이미지의 최종 판정을 단독으로 결정하는 값이 아니다.

- 저신뢰와 반복 감지는 기본 판정 결과가 아니라 재검사 사유 또는 추가 상태로 기록한다.

- 원본 이미지에서 결함이 육안으로 보이지만 anomaly score가 낮거나 heatmap이 약한 경우에는 미탐 가능성이 있으므로 후속 확인 대상으로 기록한다.
