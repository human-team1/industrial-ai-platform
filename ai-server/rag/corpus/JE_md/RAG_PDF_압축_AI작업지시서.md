# 1. 작업 배경과 목표

이 작업은 제조 현장 사용자가 챗봇에 입력하는 질문에 대해, 원문 PDF
매뉴얼을 근거로 짧고 실행 가능한 한국어 답변을 생성하기 위한 RAG
지식베이스를 만드는 과정이다.

**전체 매뉴얼을 그대로 번역하는 것이 아니라, 작업자가 실제로 질문할
가능성이 높은 증상, 원인, 점검 순서, 조치 방법, 주의사항만 압축한다.**

- 원문 PDF는 보관용으로 MinIO에 저장한다.

- 한국어 압축 문서는 RAG 검색용으로 청킹하고 임베딩한다.

- 답변 생성 시 압축 문서와 원문 PDF의 출처 페이지를 함께 제공할 수
  있어야 한다.

- 문서에 없는 내용은 추측하지 않고 “근거 문서 없음”으로 표시한다.

# 2. Agent 역할 정의

Agent는 PDF 번역가가 아니라 “RAG 문서 편집자”이다. 원문 PDF에서 현장
대응에 필요한 정보만 골라 한국어 작업자용 지식 문서로 재구성한다.

| **역할**           | **해야 할 일**                                 | **하지 말아야 할 일**                        |
|--------------------|------------------------------------------------|----------------------------------------------|
| PDF 분석자         | 목차, 페이지 범위, 장비명, 오류/점검 항목 파악 | 모델명이나 부품명을 임의로 바꾸지 않음       |
| 정보 선별자        | RAG에 필요한 증상, 원인, 점검, 조치만 추출     | 보증/법적 고지/연락처까지 전부 번역하지 않음 |
| 한국어 문서 편집자 | 현장 작업자가 이해하기 쉬운 문장으로 압축      | 원문 근거가 없는 조치 방법을 창작하지 않음   |
| 출처 관리자        | 각 압축 문단마다 원문 PDF 파일명과 페이지 기록 | 출처 페이지를 누락하지 않음                  |

# 4. 전체 작업 흐름

1.  원문 PDF 파일명, 제조사, 모델명, 버전 정보를 기록한다.

2.  PDF 전체 페이지를 훑어 목차와 섹션 구조를 파악한다.

3.  troubleshooting, maintenance, setup, calibration, error code, image
    quality, safety 중 작업자 대응에 필요한 부분만 표시한다.

4.  필요 페이지를 페이지 범위 단위로 추출표에 기록한다.

5.  각 페이지에서 증상, 원인, 점검 순서, 조치 방법, 주의사항을 한국어로
    압축한다.

6.  압축 문서를 문서 템플릿에 맞춰 작성한다.

7.  문서별 메타데이터 JSON을 생성한다.

8.  RAG 청킹 기준에 맞춰 문단을 분리한다.

9.  테스트 질문으로 검색 품질을 검증한다.

10. 원문 PDF와 압축 문서를 각각 정해진 경로에 저장한다.

|-------------------|-------------------------------------------------|----------------------------------------------|
| 1순위             | 장애 대응, 이상 증상, troubleshooting           | 사용자가 챗봇에 직접 물어볼 가능성이 높음    |
| 1순위             | 점검 순서, 유지보수 절차                        | 작업자가 즉시 수행할 수 있는 행동으로 연결됨 |
| 1순위             | 오류 코드, 경고 메시지, 상태 표시등             | 현장 문제 인식과 원인 파악에 필요함          |
| 2순위             | 설치/초기 설정 중 운영에 반복적으로 필요한 항목 | 카메라 초점, 노출, 통신 설정 등              |
| 2순위             | 안전 주의사항 중 점검 전 필수 확인 사항         | 전원 차단, 고온/회전부 접근 주의 등          |
| 제외              | 보증 조건, 법적 고지, 해외 지사 연락처          | 사용자 질의응답과 직접 관련 낮음             |

# 9. 청킹 및 RAG 반영 기준

- 한 청크는 하나의 증상 또는 하나의 점검 절차를 중심으로 구성한다.

- 청크 안에는 장비명, 증상명, 원문 페이지가 포함되어야 한다.

- 서로 다른 장비의 내용을 하나의 청크에 섞지 않는다.

- 하나의 청크 권장 길이는 한국어 기준 500-900자이다.

- 점검 순서는 번호 목록을 유지한다. RAG 답변에서 순서가 중요하기
  때문이다.

- 원문 페이지가 다른 내용은 가능하면 청크를 분리한다.

- 모호한 내용은 “원문에서 명확히 확인되지 않음”으로 표시하고 추측하지
  않는다.

1. 가이드 레일 간격이 제품 폭과 맞지 않음<br />
2. 체인 장력이 좌우 균일하지 않음<br />
3. 제품 투입 위치가 일정하지 않음<br />
4. 컨베이어 수평 상태가 맞지 않음<br />
<br />
## 점검 순서<br />
1. 제품이 쏠리는 방향과 반복 위치를 확인한다.<br />
2. 가이드 레일 간격이 제품 폭 기준에 맞는지 확인한다.<br />
3. 체인 장력과 이송 상태를 확인한다.<br />
4. 제품 투입 위치가 일정한지 확인한다.<br />
5. 컨베이어 수평 상태를 확인한다.<br />
<br />
## 조치 방법<br />
- 가이드 레일을 제품 폭 기준으로 재조정한다.<br />
- 체인 장력을 좌우 균일하게 맞춘다.<br />
- 투입 위치가 흔들리는 경우 투입 가이드를 보정한다.<br />

# 16. 최종 완료 조건

- 원문 PDF가 프로젝트 폴더 또는 MinIO 경로에 저장되어 있다.

- 페이지별 추출표가 작성되어 있다.

- 한국어 RAG 압축 문서가 Markdown 또는 TXT로 작성되어 있다.

- 메타데이터 JSON에 원문 PDF, 페이지, 장비, 모델, 키워드가 기록되어
  있다.

- 테스트 질문으로 RAG 검색 시 관련 압축 문서가 상위에 검색된다.

- 챗봇 답변이 원문 근거 기반이며 출처를 표시할 수 있다.

- 문서에 없는 질문에는 제한 응답을 반환할 수 있다.
