# 팀원용 테스트 실행 가이드

**실행 모드는 2가지**만 구분합니다: (1) 로컬 개발 실행, (2) 배포용 로컬 Docker fullstack.  
비밀번호·토큰·키 원문은 문서에 적지 않습니다.

로컬 개발 실행에서 `infra/docker-compose.yml`은 MariaDB·Redis·MinIO·Chroma 같은 **의존 인프라를 준비하는 1단계**입니다.  
즉, 로컬 개발 실행은 **「Docker 인프라 실행 + 호스트에서 Spring / FastAPI / Frontend 실행」**으로 구성됩니다.  
인프라만 단독으로 띄우는 경우도 있지만, 별도 “실행 모드”라기보다 **호스트 앱을 돌리기 위한 준비 단계**로 이해하면 됩니다.

## 1. 실행 모드 구분표

| 실행 모드 | 사용 파일 | 실행 대상 | 접속 주소 | 주 사용 상황 |
|-----------|-------------|-------------|-------------|----------------|
| **로컬 개발 실행** | 각 서버 `.env` + `infra/.env` | **1단계:** `infra/docker-compose.yml`로 MariaDB·Redis·MinIO·Chroma 실행<br>**2단계:** Spring / FastAPI / Frontend는 **호스트**에서 직접 실행 | Frontend `http://localhost:5173`<br>Spring `http://localhost:8080`<br>FastAPI `http://localhost:8001`<br>MinIO `http://localhost:9000` | 일상 개발, 기능 구현, 디버깅 |
| **배포용 로컬 Docker fullstack** | `infra/docker-compose.prod.yml` + `infra/.env.prod` | nginx·frontend·spring·ai-server·mariadb·redis·minio·chroma **전부 Docker** | `https://localhost` | 배포 전 풀스택 smoke, Google 로그인·memory bank·업로드 검사 검증 |

## 2. env 파일 역할

| 파일 | 용도 |
|------|------|
| `backend-spring/.env`, `ai-server/.env`, `frontend/.env` | **로컬 개발 실행**에서 호스트 프로세스(Spring / FastAPI / Vite)가 사용 |
| `infra/.env` | **로컬 개발 실행**에서 `docker-compose.yml` 인프라 컨테이너가 사용 |
| `infra/.env.prod` | **배포용 로컬 Docker fullstack**이 사용 |

- `.env`, `.env.prod` 등 **비밀 포함 파일은 커밋하지 않음**.
- 예시만 `*.env.example`, `infra/.env.prod.example` 등으로 버전 관리.

## 3. 이번에 특히 알아야 할 설정

### 3.1 CORS — 환경변수 이름

Spring은 `WebConfig`에서 **`app.cors.allowed-origin-patterns`** 만 읽습니다.  
**`APP_CORS_ALLOWED_ORIGINS` 는 사용하지 않습니다.**

권장:

- 로컬(Vite + 호스트 Spring):  
  `APP_CORS_ALLOWED_ORIGIN_PATTERNS=http://localhost:5173,http://localhost`
- 배포용 로컬 Docker(HTTPS):  
  `APP_CORS_ALLOWED_ORIGIN_PATTERNS=https://localhost`  
  (복수 origin 파싱 이슈 시 **단일 origin**으로 먼저 확인)

설정 위치: `backend-spring/src/main/resources/application.yml` (`app.cors`), 오버라이드는 환경변수.

### 3.2 Frontend — Google Client ID는 빌드 시점 값

Vite의 `VITE_GOOGLE_CLIENT_ID`는 **이미지 빌드(arg)** 시 박힙니다. `.env.prod`만 바꾸고 frontend 이미지를 다시 빌드하지 않으면 반영되지 않습니다.

예 (infra 디렉터리):

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod build --no-cache frontend
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d frontend nginx
```

- `VITE_GOOGLE_CLIENT_ID` 와 백엔드 검증용 `GOOGLE_CLIENT_ID` 는 **동일 OAuth Client ID**를 씁니다.
- `GOOGLE_CLIENT_SECRET` 은 **프론트에 넣지 않습니다.**

### 3.3 Google Cloud Console

Client ID에 맞춰 **Authorized JavaScript origins** 등록 예:

- 로컬 개발: `http://localhost:5173`, `http://localhost`
- 배포용 로컬 Docker: `https://localhost` (필요 시 `https://127.0.0.1`)

| 증상 | 점검 |
|------|------|
| `origin_mismatch` | JavaScript origins |
| `Missing required parameter: client_id` | `VITE_GOOGLE_CLIENT_ID` / 프론트 재빌드 |
| `Invalid CORS request` | `APP_CORS_ALLOWED_ORIGIN_PATTERNS` |

### 3.4 MinIO 버킷

검사 원본/산출물·문서·모델·보고서는 **버킷별**로 나뉩니다. Fresh volume이면 버킷이 없을 수 있습니다.

필수 버킷 이름(기본값):

- `models`
- `documents`
- `inspection-artifacts`
- `reports`

**`seed_base_model_artifacts.py`는 주로 `models` 버킷 생성 및 객체 업로드에 가깝습니다.**  
**업로드 검사**에는 **`inspection-artifacts`** 가 반드시 필요합니다.

생성 방법 (infra 디렉터리):

- PowerShell: `.\scripts\init-minio-buckets.ps1`
- prod 스택: `.\scripts\init-minio-buckets.ps1 -ComposeFile docker-compose.prod.yml -EnvFile .env.prod`
- 또는 `scripts/init-minio-buckets.sh` 를 `docker compose exec -i minio sh` 로 파이프 (WSL/Git Bash 등)

### 3.5 Base ckpt / config (memory bank 생성 전)

MinIO에 **고정 base 산출물 8종**이 있어야 `POST .../from-normal-images` 가 동작합니다.

```bash
# 호스트에서 로컬 MinIO(예: localhost:9000) — ai-server/.env 기준
cd ai-server
python scripts/seed_base_model_artifacts.py
```

배포용 local Docker (예시):

```bash
cd infra
docker compose -f docker-compose.prod.yml --env-file .env.prod exec ai-server python scripts/seed_base_model_artifacts.py
```

Object key 규격 (버킷 `models` 아래):

- `models/base/speed-object/model.ckpt`, `config.json`
- `performance-object`, `speed-texture`, `performance-texture` 동일 패턴

**참고:** `mc` 또는 콘솔에서 경로가 `models/models/base/...` 처럼 보이면, 앞의 `models`는 **버킷 이름**, 뒤 `models/base/...`는 **object key prefix**라서 정상인 경우가 많습니다.

### 3.6 Seed deployment는 추론 검증용이 아님

DB 시드의 `model_version` / `model_artifact` / `model_deployment` 는 **빈 화면 방지용 메타**로 두는 것을 권장합니다.

**실제 추론 smoke**는 정상 이미지로 memory bank를 만든 뒤, 응답에 나온 **새 `deploymentId`** 로만 `/inspections/upload` 를 호출하세요.

정식 생성 API:

`POST /api/v1/models/{modelId}/versions/from-normal-images`

우선 검증 조합 예:

- `modelCategory=OBJECT`, `modelProfile=SPEED`, `deploymentScope=ORGANIZATION`, `organizationId` 는 시드 조직 또는 본인 조직

## 4. 로컬 개발 실행

### 4.1 1단계: 인프라 (docker-compose.yml)

```powershell
cd infra
docker compose --env-file .env up -d
docker compose --env-file .env ps
```

- **`docker volume prune` 사용 금지**(팀 규칙). 필요한 볼륨만 이름 확인 후 선택 삭제.
- `.env` 의 DB 비밀번호를 바꿨는데 **기존 MariaDB 볼륨**이 남아 있으면 접속 거절 가능 → 비밀번호 맞추거나 해당 볼륨 제거 후 재초기화.
- 인프라만 켜 두고 당장 앱은 안 돌리는 경우도 **같은 1단계**입니다(별도 실행 모드로 나누지 않음).

### 4.2 2단계: 호스트 앱 — Spring (`backend-spring/.env`)

- `DB_HOST=localhost`, `DB_PORT=3307` … — **호스트에서 실행 시 DB는 `localhost`** (Compose 서비스명 `mariadb` 는 **컨테이너 안**에서만).
- `REDIS_HOST=localhost`, `MINIO_ENDPOINT=http://localhost:9000`, `AI_SERVER_BASE_URL=http://localhost:8001`, `CHROMA_HOST=localhost` 등.
- `APP_CORS_ALLOWED_ORIGIN_PATTERNS=http://localhost:5173,http://localhost`

```powershell
cd backend-spring
.\gradlew.bat bootRun --args="--spring.profiles.active=local"
```

### 4.3 2단계: 호스트 앱 — FastAPI (`ai-server/.env`)

- `MINIO_ENDPOINT=http://localhost:9000`, `CHROMA_HOST=localhost`, `REDIS_HOST=localhost` 등 호스트 기준.

### 4.4 2단계: 호스트 앱 — Frontend (`frontend/.env`)

- `VITE_API_BASE_URL=/api/v1` (프록시·Nginx 경유 시) 또는 `http://localhost:8080/api/v1` 등 직접 API 호출 방식에 맞게 설정.
- `VITE_GOOGLE_CLIENT_ID=<Client ID>`

```powershell
cd frontend
npm install
npm run dev
```

## 5. 배포용 로컬 Docker fullstack

### TLS

`infra/nginx/ssl/fullchain.pem`, `privkey.pem` 필요. 로컬은 self-signed 로 충분 (`infra/nginx/ssl/README.md` 참고).

### 기동

```powershell
cd infra
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
```

### 접속

- `https://localhost`
- `https://localhost/api/v1/health`

브라우저 인증서 경고는 로컬에서 정상입니다.

### CORS (`.env.prod`)

```env
APP_CORS_ALLOWED_ORIGIN_PATTERNS=https://localhost
```

### MinIO

- `.\scripts\init-minio-buckets.ps1 -ComposeFile docker-compose.prod.yml -EnvFile .env.prod`
- `seed_base_model_artifacts.py` 는 위 절의 3.5 참고

## 7. 장애별 빠른 원인표

| 증상 | 원인 | 조치 |
|------|------|------|
| Missing required parameter: client_id | `VITE_GOOGLE_CLIENT_ID` 누락 / 프론트 미재빌드 | `VITE_*` 수정 후 frontend **no-cache build** |
| origin_mismatch | Google OAuth JavaScript origin 미등록 | Cloud Console origins 추가 |
| Invalid CORS request | Spring CORS 불일치 | `APP_CORS_ALLOWED_ORIGIN_PATTERNS` 확인 |
| Access denied (DB) | `.env` 비밀번호 ≠ 기존 DB 볼륨 | 비밀 맞추거나 볼륨 재초기화 |
| 검사 파일 업로드 실패(500, MinIO) | `inspection-artifacts` 버킷 없음 | `init-minio-buckets` 실행 |
| memory bank 생성 실패 | base ckpt/config 객체 없음 | `seed_base_model_artifacts.py` |
| `/ai/`, `/minio/`, `/chroma/` 외부 403 | nginx에서 의도적 차단 | 정상 |
