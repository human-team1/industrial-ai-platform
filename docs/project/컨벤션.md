# 개발 컨벤션

프로젝트 협업과 코드 품질을 위한 최소 기준입니다. 상세 권한/API/DB 규칙은 각 기준 문서를 우선합니다.

## 브랜치

- `main`: 배포/제출 기준 브랜치
- `develop`: 개발 통합 브랜치
- 작업 브랜치: `feat/*`, `fix/*`, `docs/*`, `refactor/*`, `test/*`, `chore/*`, `hotfix/*`, `release/*`
- `main`에는 직접 push하지 않습니다.

## 커밋

형식:

```text
type: 작업 내용
```

허용 type:

- `feat`
- `fix`
- `docs`
- `refactor`
- `test`
- `chore`

하나의 커밋에는 가능하면 하나의 작업만 담습니다.

## PR

PR 제목 권장 형식:

```text
[type] 작업 내용
```

PR 본문에는 아래 항목을 간결하게 포함합니다.

- 작업 내용
- 주요 변경 사항
- 테스트/검증 내용
- 참고 사항
- UI 변경 시 스크린샷

## 아키텍처 원칙

### Frontend

- FSD 구조를 따릅니다.
- 의존 방향은 `app -> pages -> widgets -> features -> entities -> shared`입니다.
- API 호출은 `shared/api` 또는 feature별 `api` 계층에 둡니다.

### Spring Backend

- Hexagonal Architecture를 따릅니다.
- Controller는 비즈니스 로직을 갖지 않습니다.
- Service는 Web DTO나 JPA Entity에 직접 의존하지 않습니다.
- 외부 연동은 port/adapter로 분리합니다.

### FastAPI AI Server

- `api -> application -> domain` 방향을 유지합니다.
- `infrastructure`는 domain port 구현체를 둡니다.
- Router에서 구현체를 직접 생성하지 않고 `container`에서 조립합니다.

## API 규칙

- 외부 API prefix는 `/api/v1`입니다.
- 일반 성공 응답은 `{ "success": true, "data": ..., "message": "..." }` 형식을 사용합니다.
- 실패 응답은 RFC 9457 Problem Details 형식을 기본으로 합니다.
- 파일 다운로드, 스트리밍, health check, 204 응답은 예외로 둘 수 있습니다.

상세 API는 [API.md](API.md)를 기준으로 합니다.

## 네이밍

| 영역 | 규칙 |
| --- | --- |
| Python 변수/함수 | `snake_case` |
| Java 변수/메서드 | `camelCase` |
| TypeScript/React | 기존 코드베이스 컨벤션 우선 |
| 클래스 | `PascalCase` |
| 상수 | `UPPER_SNAKE_CASE` |
| Boolean | `is/has/can` 등 상태가 드러나는 접두어 사용 |

## 보안

- `.env`, `.env.*`, 인증서, API Key, DB 비밀번호, Google OAuth Client Secret, JWT Secret은 커밋하지 않습니다.
- `*.pt`, `*.onnx`, `*.ckpt`, 영상 파일 등 대용량 산출물은 Git에 커밋하지 않습니다.
- 공유가 필요한 설정은 실제 값이 없는 `.env.example`에만 반영합니다.

## 제출 전 점검

- 불필요한 콘솔 로그/디버깅 코드 제거
- 민감정보 포함 여부 확인
- `git status`와 변경 파일 확인
- 변경 범위에 맞는 최소 검증 수행
